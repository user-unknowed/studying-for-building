0. 导读：为什么专门做一章"源码编辑"

前九章都在教"怎么写代码"，这一章换个视角：怎么读、怎么改一个已经跑在线上的真实项目。材料不用虚构——就用本站自己的源码：

  • worker.js —— 在 Cloudflare 边缘节点上运行，决定 /10.html 这类请求返回什么；
  • deploy.py —— 在开发机上运行，把 site/ 目录一键发布上线；
  • editor.js —— 在浏览器里运行，就是本章那个可以直接改代码的编辑器。

三份源码恰好覆盖一个最小 Web 项目的三层：边缘路由层、发布流水线层、前端交互层。每份都是完整可运行的代码（构建时经过真实语法检查），并以两种形式同时呈现在本章：

  1. 第 1 节的编辑器里，它们是可以直接修改的纯文本；
  2. 第 2 节的源码清单里，它们是带行号、带详尽注释的全文。

两处内容逐字节一致——由同一个构建脚本（build_chapter10.py）从同一份源码字符串生成，不存在"演示代码与实际代码对不上"的问题。

1.3 实现要点

  • 数据来源：<script type="text/plain" data-file="...">——浏览器不执行这种 script，正好当"嵌入页面的纯文本文件仓库"用，避免把源码塞进 JS 字符串里的转义地狱。全页共 3 个数据块、1 个可执行脚本。
  • 高亮器：一条正则 + 四个捕获组（注释 > 字符串 > 数字 > 关键字）。优先级顺序是关键——注释和字符串必须先于关键字匹配，否则字符串里的 "function" 会被误染色。
  • 状态复位：带 g 标志的正则对象是有状态的（lastIndex），复用前必须归零，这是高亮器最常见的隐性 bug。
  • 转义顺序：HTML 转义必须先替换 &，再替换 < 和 >，否则会把第一次替换产生的实体再转义一次。
  • 滚动同步：行号列、编辑区、预览区三者共用 13px/1.55 的行高，保证每行严格对齐；scroll 事件单向驱动行号列，避免双向同步的抖动。
  • 本地保存：localStorage 以 sce:文件名 为键，一个文件一份草稿；重置即删键。

2.1 worker.js —— Cloudflare Worker 边缘路由

 1// =====================================================================
 2// worker.js —— 本站 Cloudflare Worker 边缘路由（教学注释版）
 3// ---------------------------------------------------------------------
 4// 真实文件：/workspace/worker_kv.js（内容存 KV）；本版把 KV 换成内存表，
 5// 路由 / 404 / 缓存头逻辑与线上完全一致，可以直接在本页编辑器里改着玩。
 6//
 7// 执行模型：请求到达全球 300+ 个边缘节点之一，节点上的 V8 isolate
 8// 调用一次下面的 fetch() 并返回响应。没有"服务器进程"——
 9// 每个请求都是一次独立的函数调用，冷启动以毫秒计。
10// =====================================================================
11
12// ── 1. 路由表：路径 → Content-Type ─────────────────────────────────
13// Content-Type 决定浏览器如何处理响应体：
14//   text/html → 解析成 DOM；text/css → 当样式表应用；其余按二进制下载
15const ROUTES = {
16  "/":                 "text/html; charset=utf-8",
17  "/index.html":       "text/html; charset=utf-8",
18  "/01.html":          "text/html; charset=utf-8",
19  "/02.html":          "text/html; charset=utf-8",
20  "/03.html":          "text/html; charset=utf-8",
21  "/04.html":          "text/html; charset=utf-8",
22  "/05.html":          "text/html; charset=utf-8",
23  "/06.html":          "text/html; charset=utf-8",
24  "/07.html":          "text/html; charset=utf-8",
25  "/08.html":          "text/html; charset=utf-8",
26  "/09.html":          "text/html; charset=utf-8",
27  "/10.html":          "text/html; charset=utf-8",
28  "/assets/style.css": "text/css; charset=utf-8",
29};
30
31// ── 2. 入口：导出一个带 fetch 方法的对象 ────────────────────────────
32// Workers 模块语法约定：default 导出对象上的 fetch 就是请求处理函数
33export default {
34  async fetch(request) {
35    // 2.1 解析请求 URL，只取路径部分（?查询参数 和 #锚点 都不参与路由）
36    const { pathname } = new URL(request.url);
37
38    // 2.2 路径归一化：访问根路径等价于访问 /index.html
39    //     用户直接敲域名不带文件名时，也能落到首页
40    const key = pathname === "/" ? "/index.html" : pathname;
41
42    // 2.3 查路由表（白名单思路：默认拒绝，命中才放行）
43    const type = ROUTES[key];
44    if (!type) {
45      // 404 也要显式声明 Content-Type，
46      // 防止浏览器把错误文本当 HTML 渲染出奇怪的页面
47      return new Response("Not Found: " + key, {
48        status: 404,
49        headers: { "Content-Type": "text/plain; charset=utf-8" },
50      });
51    }
52
53    // 2.4 真实站点在这里从 KV 读出 gzip+base64 内容并解压后返回
54    //     （完整解压流程见下方"逐行讲解"表）；教学版返回占位页面
55    const body = "<!DOCTYPE html><p>这里本应返回 " + key + " 的真实内容</p>";
56
57    // 2.5 构造响应：缓存头让边缘节点替源站挡住重复流量
58    //     public        → 浏览器和 CDN 都可以缓存
59    //     max-age=3600  → 缓存 1 小时，期间命中缓存不再回源
60    return new Response(body, {
61      headers: {
62        "Content-Type": type,
63        "Cache-Control": "public, max-age=3600",
64      },
65    });
66  },
67};

真实文件是 /workspace/worker_kv.js（内容存 KV）。上表所列行为与线上完全一致；把上面的 ROUTES 表删掉一行，再访问对应路径就会得到 404——可以在编辑器里改了之后对照第 3 节的流程在本地跑起来验证。

行号代码讲解

33export default {Cloudflare Workers 的模块入口约定：default 导出对象上的 fetch 就是请求处理函数，每个请求触发一次调用
36new URL(request.url)解析请求行 URL，只取 pathname；查询参数与锚点不参与路由
40pathname === "/" ? ...路径归一化：根路径等价于 /index.html，用户直接敲域名也能落到首页
44if (!type) → 404查表未命中就构造 404 响应。注意连错误响应也显式声明了 Content-Type: text/plain，防止浏览器把错误文本当 HTML 渲染
55const body = ...教学版返回占位内容；真实站点（worker_kv.js）在这一步从 KV 读出 gzip+base64 数据，用 DecompressionStream 解压后返回

2.2 deploy.py —— 一键部署脚本

deploy.pyPython · 部署脚本 · 运行在开发机 · 107 行↑ 在编辑器中打开
  1# -*- coding: utf-8 -*-
  2# =====================================================================
  3# deploy.py —— 把 site/ 目录一键发布到 Cloudflare Pages（教学注释版）
  4# ---------------------------------------------------------------------
  5# 真实文件：/workspace/deploy_pages.py；本版保留完整流程，
  6# 删去少量工程细节，聚焦"一次发布到底发生了什么"。
  7#
  8# 发布静态站到边缘网络只需三步：
  9#   ① 指纹：算出每个文件的 SHA-256（内容寻址——改一个字符指纹就变）
 10#   ② 上传：把文件本体按批次送进 Pages 资产仓库（同指纹自动去重）
 11#   ③ 装订：提交"路径 → 指纹"清单，Cloudflare 把资产装订成一次新部署
 12# =====================================================================
 13import base64          # 把二进制文件编码成可放进 JSON 的文本
 14import hashlib         # 计算 SHA-256 内容指纹
 15import json            # 序列化上传清单
 16import mimetypes       # 按扩展名推断 Content-Type（.html → text/html）
 17import os              # 遍历目录、读取环境变量
 18import sys             # 出错时以非零码退出
 19
 20import requests        # 唯一的第三方依赖：同步 HTTP 客户端
 21
 22# ── 配置区：改这两行就能发布别的站点 ────────────────────────────────
 23SITE_DIR = "site"                  # 待发布的静态文件目录
 24PROJECT  = "java-sql-ai-tutorial"  # Pages 项目名（决定最终域名）
 25API      = "https://api.cloudflare.com/client/v4"   # Cloudflare API 根地址
 26ACCOUNT  = os.environ["CLOUDFLARE_ACCOUNT_ID"]      # 账号 ID（环境变量传入）
 27
 28
 29def sha256_of(path):
 30    """流式计算文件指纹：每次只读 1MB，大文件也不会撑爆内存。"""
 31    h = hashlib.sha256()
 32    with open(path, "rb") as f:
 33        # iter(callable, sentinel)：反复调用 f.read，直到读到空字节串 b""
 34        for chunk in iter(lambda: f.read(1 << 20), b""):
 35            h.update(chunk)
 36    return h.hexdigest()           # 64 位十六进制字符串，即文件指纹
 37
 38
 39def collect_assets():
 40    """遍历 SITE_DIR，返回 (待上传资产列表, 路径→指纹 清单)。"""
 41    assets, manifest = [], {}
 42    for root, _, files in os.walk(SITE_DIR):       # os.walk 递归下钻子目录
 43        for name in files:
 44            full = os.path.join(root, name)
 45            # 逻辑路径必须以 / 开头且用正斜杠——这是 Pages 清单的硬性约定
 46            rel = "/" + os.path.relpath(full, SITE_DIR).replace(os.sep, "/")
 47            with open(full, "rb") as f:
 48                raw = f.read()
 49            ctype = mimetypes.guess_type(full)[0] or "application/octet-stream"
 50            # 注意：key 是内容指纹，不是文件名！
 51            # 同一文件在多次部署间天然去重，改过的文件指纹不同才需重新上传
 52            assets.append({
 53                "key": sha256_of(full),
 54                "value": base64.b64encode(raw).decode(),   # 二进制 → base64 文本
 55                "base64": True,       # 告诉 API value 字段是 base64 编码
 56                "contentType": ctype,
 57            })
 58            manifest[rel] = assets[-1]["key"]       # 清单：路径 → 指纹
 59            print(f"  {rel:32s} {assets[-1]['key'][:12]}...")
 60    return assets, manifest
 61
 62
 63def main():
 64    token = os.environ.get("CLOUDFLARE_API_TOKEN")
 65    if not token:
 66        sys.exit("请先设置环境变量 CLOUDFLARE_API_TOKEN")
 67    auth = {"Authorization": "Bearer " + token}
 68
 69    assets, manifest = collect_assets()
 70
 71    # ── ① 用长效令牌换一次性上传令牌（JWT，约 30 分钟有效）──────────
 72    #      资产上传走专门的资产接口，只认这个短命 JWT，缩小凭证暴露面
 73    r = requests.get(
 74        f"{API}/accounts/{ACCOUNT}/pages/projects/{PROJECT}/upload-token",
 75        headers=auth,
 76    )
 77    r.raise_for_status()               # 4xx/5xx 直接抛异常，不带病往下走
 78    jwt = r.json()["result"]["jwt"]
 79
 80    # ── ② 分批上传：单批请求体控制在 ~240KB，避免超过网关限制 ───────
 81    batch, batch_size = [], 0
 82    for a in assets:
 83        if batch and batch_size + len(a["value"]) > 240 * 1024:
 84            requests.post(f"{API}/pages/assets/upload",
 85                          headers={"Authorization": "Bearer " + jwt},
 86                          json=batch).raise_for_status()
 87            batch, batch_size = [], 0   # 清空，开始攒下一批
 88        batch.append(a)
 89        batch_size += len(a["value"])
 90    if batch:                           # 循环结束后别忘了最后一批
 91        requests.post(f"{API}/pages/assets/upload",
 92                      headers={"Authorization": "Bearer " + jwt},
 93                      json=batch).raise_for_status()
 94
 95    # ── ③ 提交清单：Cloudflare 按清单把资产"装订"成一次新部署 ────────
 96    #      files 参数传 (文件名, 内容, 类型) → 以 multipart 表单发送
 97    r = requests.post(
 98        f"{API}/accounts/{ACCOUNT}/pages/projects/{PROJECT}/deployments",
 99        headers=auth,
100        files={"manifest": (None, json.dumps(manifest))},
101    )
102    r.raise_for_status()
103    print("部署完成 →", r.json()["result"]["url"])
104
105
106if __name__ == "__main__":
107    main()

真实文件是 /workspace/deploy_pages.py。本章上线用的就是同一套「指纹 → 上传 → 装订」三步流程，只是把 requests 调用换成了等价的 API 直调。

行号代码讲解
20import requests唯一的第三方依赖。部署脚本不需要异步并发，同步 HTTP 客户端最简单可靠
23SITE_DIR = "site"配置区集中放在文件顶部：改两个字符串就能发布另一个站点，这是脚本可复用的最低成本设计
29def sha256_of(path)流式读取（每次 1MB）计算指纹。iter(callable, sentinel) 是 Python 惯用的“读到空值为止”循环，大文件不会撑爆内存

53"key": sha256_of(full)上传资产的 key 是内容指纹而不是文件名——同一文件在多次部署间天然去重，本次上线只需真正上传改动过的文件
74upload-token用长效 API 令牌换取一次性 JWT（约 30 分钟有效）。资产上传接口只认这个短命令牌，缩小长效凭证的暴露面
83240 * 1024单批请求体上限的经验值。分批上传避免超过网关对请求体大小的限制

 21  /* HTML 转义：& 必须最先替换。
 22   * 若先替换 <，产生的 &lt; 里的 & 会被二次转义成 &amp;lt;。 */
 23  function esc(s) {
 24    return s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
 25  }
 26
 27  function highlight(code, lang) {
 28    const re = lang === "py" ? PY_RE : JS_RE;
 29    re.lastIndex = 0;            // 带 g 标志的正则是"有状态"的，用前必须归零
 30    let out = "", last = 0, m;
 31    while ((m = re.exec(code)) !== null) {
 32      out += esc(code.slice(last, m.index));              // 词元之间的普通文本
 33      const cls = m[1] ? "c" : m[2] ? "s" : m[3] ? "m" : "k";  // 注释/字符串/数字/关键字
 34      out += '<span class="' + cls + '">' + esc(m[0]) + "</span>";
 35      last = m.index + m[0].length;
 36    }
 37    return out + esc(code.slice(last));
 38  }
 39
 40  /* ── 2. 收集要编辑的源码文件 ──────────────────────────────────── */
 41  const FILES = [];
 42  const nodes = document.querySelectorAll('script[type="text/plain"][data-file]');
 43  for (let i = 0; i < nodes.length; i++) {
 44    const name = nodes[i].getAttribute("data-file");
 45    FILES.push({
 46      name: name,
 47      lang: /\.py$/.test(name) ? "py" : "js",
 48      original: nodes[i].textContent.replace(/^\n/, ""),  // 去掉紧贴标签的首个换行
 49    });
 50  }
 51
 52  /* ── 3. 抓取页面元素 ──────────────────────────────────────────── */
 53  function $(id) { return document.getElementById(id); }
 54  const editor  = $("sce-code");      // 可编辑的 textarea
 55  const gutter  = $("sce-gutter");    // 行号列
 56  const preview = $("sce-preview");   // 高亮预览区
 57  let current = null;                 // 当前打开的文件对象
 58
 59  /* ── 4. 行号 / 统计 / 光标位置 ────────────────────────────────── */
 60  function refreshGutter() {
 61    const lines = editor.value.split("\n").length;
 62    let html = "";
 63    for (let i = 1; i <= lines; i++) html += i + "\n";
 64    gutter.textContent = html;
 65    $("sce-lines").textContent = lines;
 66    $("sce-chars").textContent = editor.value.length;
 67  }
 68
 69  function refreshCursor() {
 70    const rows = editor.value.slice(0, editor.selectionStart).split("\n");
 71    $("sce-pos").textContent =
 72      "行 " + rows.length + "，列 " + (rows[rows.length - 1].length + 1);
 73  }
 74
 75  /* ── 5. 高亮预览：把编辑区当前内容渲染成带颜色的 HTML ─────────── */
 76  function renderPreview() {
 77    preview.innerHTML = "<code>" + highlight(editor.value, current.lang) + "</code>";
 78  }
 79
 80  /* ── 6. 打开文件：初始化编辑区（优先恢复本地草稿）──────────────── */
 81  function openFile(file) {
 82    current = file;
 83    let saved = null;
 84    try { saved = localStorage.getItem("sce:" + file.name); } catch (e) {}
 85    editor.value = saved !== null ? saved : file.original;
 86    const tabs = document.querySelectorAll(".sce-tab");
 87    for (let i = 0; i < tabs.length; i++) {
 88      tabs[i].classList.toggle("active", tabs[i].getAttribute("data-file") === file.name);
 89    }
 90    $("sce-filename").textContent = file.name + (saved !== null ? "（含本地修改）" : "");
 91    refreshGutter();
 92    refreshCursor();
 93    renderPreview();
 94  }
 95
 96  /* ── 7. 事件绑定 ──────────────────────────────────────────────── */
 97  editor.addEventListener("input", function () {
 98    // 自动保存：每次按键都写 localStorage，刷新页面不丢
 99    try { localStorage.setItem("sce:" + current.name, editor.value); } catch (e) {}
100    refreshGutter();
101    renderPreview();
102  });
103  editor.addEventListener("keyup", refreshCursor);
104  editor.addEventListener("click", refreshCursor);
105
106  /* 行号列与编辑区 / 预览区纵向滚动保持同步（单向驱动，避免抖动） */
107  editor.addEventListener("scroll", function () { gutter.scrollTop = editor.scrollTop; });
108  preview.addEventListener("scroll", function () { gutter.scrollTop = preview.scrollTop; });
109
110  /* 按 Tab 插入两个空格而不是把焦点切走——编辑器的基本礼仪 */
111  editor.addEventListener("keydown", function (e) {
112    if (e.key === "Tab") {
113      e.preventDefault();
114      const s = editor.selectionStart, t = editor.selectionEnd;
115      editor.value = editor.value.slice(0, s) + "  " + editor.value.slice(t);
116      editor.selectionStart = editor.selectionEnd = s + 2;
117      editor.dispatchEvent(new Event("input"));   // 手动触发，走统一的保存+刷新
118    }
119  });
120
121  $("sce-copy").onclick = function () {
122    const btn = this;
123    const done = function () {
124      btn.textContent = "已复制 ✓";
125      setTimeout(function () { btn.textContent = "复制"; }, 1200);
126    };
127    if (navigator.clipboard && navigator.clipboard.writeText) {
128      navigator.clipboard.writeText(editor.value).then(done);
129    } else {                       // 老浏览器退化方案：选中全文再复制
130      editor.select();
131      document.execCommand("copy");
132      editor.setSelectionRange(0, 0);
133      done();
134    }
135  };
136
137  $("sce-reset").onclick = function () {
138    if (!confirm("放弃本地修改，恢复本章原始源码？")) return;
139    try { localStorage.removeItem("sce:" + current.name); } catch (e) {}
140    openFile(current);
141  };
142
143  $("sce-download").onclick = function () {
144    const a = document.createElement("a");
145    a.href = URL.createObjectURL(new Blob([editor.value], { type: "text/plain" }));
146    a.download = current.name;
147    a.click();
148    URL.revokeObjectURL(a.href);   // 用完立刻释放，避免内存泄漏
149  };
150
151  /* 在"可编辑纯文本"与"高亮预览"两个视图之间切换 */
152  $("sce-toggle").onclick = function () {
153    const on = document.body.classList.toggle("sce-preview-on");
154    this.textContent = on ? "返回编辑" : "高亮预览";
155  };
156
157  /* 文件标签页切换 */
158  const tabs = document.querySelectorAll(".sce-tab");
159  for (let i = 0; i < tabs.length; i++) {
160    tabs[i].onclick = function () {
161      const want = this.getAttribute("data-file");
162      for (let j = 0; j < FILES.length; j++) {
163        if (FILES[j].name === want) { openFile(FILES[j]); return; }
164      }
165    };
166  }
167
168  if (FILES.length) openFile(FILES[0]);   // 默认打开第一个文件
169})();

行号代码讲解
18const JS_RE = /.../g迷你高亮器的全部秘密：一条正则四个捕获组，从左到右优先级递减——注释、字符串、数字、关键字。顺序错了，字符串里的关键字会被误染色
29re.lastIndex = 0带 g 标志的正则是“有状态”的：上次 exec 停在哪，这次就从哪继续。复用前不归零，第二次高亮就会错乱——这是高亮器最常见的隐性 bug
23function esc(s)HTML 转义顺序：& 最先。如果先替换 <，第一次产生的 < 里的 & 会被二次转义成 &lt;
42script[type="text/plain"]用不执行的 script 标签当数据仓库：浏览器不渲染也不执行它，把源码原样存在 DOM 里，比塞进 JS 字符串干净——无需转义引号和反斜杠
99localStorage.setItem“自动保存”的实现就一行：每次输入都写 localStorage，写入成本远低于按键频率，不需要防抖
107gutter.scrollTop = ...行号列 overflow:hidden 隐藏滚动条，由编辑区的 scroll 事件单向驱动。单向同步避免双向绑定造成的抖动循环
112e.key === "Tab"拦截 Tab 键插入两个空格。preventDefault 是关键，否则焦点会跳到下一个控件， textarea 就“打不了字”了
148URL.revokeObjectURL(a.href)下载完成后立刻释放 Blob URL。不释放的话，每次下载都在内存里漏一个对象

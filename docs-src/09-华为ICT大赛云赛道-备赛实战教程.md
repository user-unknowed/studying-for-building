## 1. 华为ICT大赛是什么

华为ICT大赛是华为公司自 **2015 年**起主办的、面向全球高校师生的年度 ICT 赛事，定位为国际化竞技和交流平台。

- **规模**：截至第十届（2025-2026）累计报名 **118 万人以上**，覆盖院校 2000+、国家和地区 100+。第十届单届报名 22 万余人，中国区 15.4 万人为最大赛区。
- **认可度**：在中国被纳入《全国普通高校大学生竞赛项目榜单》；在海外被纳入 UNESCO 全球技能学院关键伙伴旗舰项目。
- **当前赛季**：第十一届（2026-2027）已于 2026 年 9 月启动报名。

### 1.2 七大赛事体系

第十一届大赛设七大赛事，其中学生可报名的主力是**实践赛**：

## 3. 云计算通俗原理

这是云赛道最核心的基础概念。用最通俗的方式讲清楚。

### 3.1 虚拟化：一台物理服务器切成多台云服务器

**一句话定义**：虚拟化把一台物理服务器的 CPU、内存、磁盘、网卡，切分成若干台相互隔离的"虚拟机"，每台都能像独立服务器一样开机、装系统、跑程序。

**打比方**：一栋大楼（物理服务器）传统上只有一户住，白天房间空着、利用率极低。物业把大楼隔成很多小公寓（虚拟机）分租出去，每户水电表独立（资源隔离），用多少付多少。

**核心机制**：

1. **Hypervisor（虚拟化层）**：位于硬件与操作系统之间的"二房东"，负责分配 CPU 时间片、内存页、磁盘块和网卡带宽。华为云底层基于 KVM
2. **资源隔离**：每台 ECS 独享分配到的 vCPU/内存，一台虚拟机崩溃不影响其他虚拟机
3. **弹性调度**：虚拟机本质是"文件 + 配置"，可以跨物理机热迁移、随时变更规格

### 3.2 三种服务模型：IaaS、PaaS、SaaS

**打比方**——想吃披萨的三种方式：

| 模型 | 比喻 | 你管理什么 | 华为云代表 |
|---|---|---|---|
| 自建机房 | 在家从头做：和面、买烤箱、生火 | 全部：机房、硬件、系统、应用 | 传统 IDC |
| **IaaS** | 租厨房：水电和烤箱有人管，你只管做披萨 | 操作系统、中间件、应用 | ECS、EVS、VPC |
| **PaaS** | 买半成品：饼底酱料都备好，你只管加料烤 | 应用和数据 | CCE、RDS、ModelArts |
| **SaaS** | 下馆子：坐下就吃 | 什么都不管，用就行 | WeLink、钉钉 |

**比赛视角**：云赛道实验横跨 IaaS 和 PaaS——既要在 ECS 上自己装系统装软件，也要用 RDS 免去自建数据库、用 CCE 免去自建 K8s 集群。

### 3.3 三种部署模式

| 模式 | 谁用 | 特点 |
|---|---|---|
| 公有云 | 多家租户共享 | 按需付费、分钟级开通、弹性最强（比赛就考这个） |
| 私有云 | 单一机构独享 | 数据可控、定制化强、成本高（华为云 Stack） |
| 混合云 | 两边都要 | 敏感业务放私有云、弹性业务放公有云 |

### 3.4 弹性：把算力当水电用

传统机房：预估双十一流量 → 提前 3 个月采购服务器 → 大促过后全部闲置。
云计算：配一条 AS 策略 → CPU 超 70% 自动加机器 → 流量回落自动释放，按量计费。

**两种弹性**：

- **纵向弹性（Scale Up/Down）**：单台机器升配/降配（ECS 变更规格）
- **横向弹性（Scale Out/In）**：机器数量加减（AS + ELB 是标配组合）

### 3.5 三种存储：块、文件、对象

| 类型 | 比喻 | 华为云服务 | 典型场景 |
|---|---|---|---|
| 块存储 | 整块硬盘，格式化后只能给一台机器用 | EVS 云硬盘 | ECS 系统盘/数据盘 |
| 文件存储 | 共享网盘，多机可同时挂载 | SFS 弹性文件服务 | 共享目录、高性能计算 |
| 对象存储 | 仓库格子：存"整个文件 + 元数据标签"，走 HTTP 访问 | OBS 对象存储 | 图片视频、备份、静态网站 |

**判别口诀**：要格式化装系统 → EVS；要多机共享目录 → SFS；要存海量文件走网络 → OBS。

### 3.6 一张图理解一个云上 Web 架构

```
用户 ── EIP/域名 ── ELB（流量分发、健康检查）
                        │
        ┌───────────────┼───────────────┐
     ECS-1            ECS-2           ECS-3      ← AS 弹性伸缩组（按负载增减）
        │               │               │
        └──── VPC 虚拟私有云（安全组当防火墙）────┘
                        │
             RDS 主备数据库  +  OBS 存图片视频
```

- 用户请求从 ELB 分发到多台 ECS（Web 层）
- ECS 把结构化数据存进 RDS（数据库层），图片视频放 OBS（存储层）
- 流量高峰时 AS 自动扩容 ECS，ELB 自动把新机器纳入分发列表

## 4. 核心知识点详解：华为云服务

### 4.1 ECS 弹性云服务器

**一句话定义**：ECS（Elastic Cloud Server）就是云上的一台"电脑"，CPU、内存、磁盘、操作系统任选，分钟级开通，随时退订。

**购买五要素**：

| 要素 | 怎么选 | 备注 |
|---|---|---|
| 区域/可用区 | 就近选；多可用区可抗机房级故障 | 比赛环境一般指定区域 |
| 规格 | 通用计算型（Web）、内存优化型（数据库）、GPU 型（AI） | vCPU:内存 常见 1:1/1:2/1:4 |
| 镜像 | 公共镜像（官方 OS）/ 私有镜像 / 市场镜像（预装软件） | 比赛常指定 CentOS/openEuler |
| 磁盘 | 系统盘（必选）+ 数据盘（可选） | 类型见 4.3 |
| 网络 | VPC + 子网 + 安全组 + 是否绑 EIP | 公网访问必须绑 EIP |

**关键操作流程**：

1. 控制台搜索 "ECS" → 购买 → 按上表填五要素
2. 设置登录凭证：**密码**（简单直接）或 **SSH 密钥对**（更安全）
3. 等待 1-2 分钟状态变为"运行中"
4. 远程登录：Linux 用 SSH（`ssh root@EIP`）或控制台 VNC；Windows 用 MSTSC 远程桌面

**计费模式**：按需（秒级计费，练习首选，用完立刻释放）vs 包周期（包月包年，便宜但退订难）。**练习/比赛用按需，练完及时释放，避免烧钱**。

### 4.2 VPC、子网与安全组：云上的网络底座

**VPC（Virtual Private Cloud）**：一块逻辑隔离的虚拟网络空间，相当于你在云上的"私人机房"。所有 ECS、RDS、ELB 都要放进某个 VPC 里。

**核心组件**：

| 组件 | 作用 | 要点 |
|---|---|---|
| VPC | 整个私有网段 | 用 CIDR 表示，如 `192.168.0.0/16` |
| 子网 | VPC 内的 smaller 网段 | 不同可用区可用不同子网 |
| 安全组 | ECS 级别的虚拟防火墙 | **有状态**：入方向默认全拒绝，出方向默认全允许 |
| EIP | 弹性公网 IP | 可独立保留，随时绑定/解绑 ECS |
| 路由表 | 子网的转发规则 | 默认路由就能同 VPC 互通；跨 VPC 用对等连接 |

**典型安全组规则（Web 服务器）**：

| 方向 | 协议 | 端口 | 源/目标 | 说明 |
|---|---|---|---|---|
| 入方向 | TCP | 22 | 0.0.0.0/0 | SSH 远程登录 |
| 入方向 | TCP | 80 | 0.0.0.0/0 | HTTP 网站访问 |
| 入方向 | ICMP | 全部 | 0.0.0.0/0 | 允许 ping 测试 |
| 出方向 | 全部 | 全部 | 0.0.0.0/0 | 默认放行 |

> **云上排障第一反应：端口不通 → 先查安全组**。这是所有新手（和比赛中）最常见的故障来源。

### 4.3 EVS 云硬盘与备份

**EVS（Elastic Volume Service）**：云上的虚拟硬盘，挂给 ECS 当系统盘/数据盘。

| 磁盘类型 | 性能 | 适用 |
|---|---|---|
| 普通型（SATA） | 最低成本 | 开发测试、低频访问 |
| 高 IO 型（SAS） | 中等 | 普通业务应用 |
| 超高 IO 型（SSD） | 最高 | 数据库、高性能需求 |

**新数据盘挂载三步**（买盘后 Linux 里还要初始化）：

```bash
fdisk -l                      # 确认新盘符，如 /dev/vdb
mkfs.ext4 /dev/vdb            # 格式化为 ext4
mkdir /data && mount /dev/vdb /data   # 挂载后 df -h 验证
```

**快照（Snapshot）**：磁盘某时刻的只读副本，回滚就恢复到那一刻——改崩系统前的救命稻草。
**备份（CBR）**：整机的备份+恢复，比赛里常考"对 ECS 做备份/恢复"。

### 4.4 OBS 对象存储

**一句话定义**：OBS（Object Storage Service）存的是"对象"（文件 + 元数据），容量近乎无限，通过 HTTP 访问，是放图片、视频、备份、静态网页的首选。

**核心概念**：

- **桶（Bucket）**：存对象的容器，**名称全局唯一**（所有华为云用户里不能重名）
- **存储类别**：

| 类别 | 价格 | 访问时延 | 场景 |
|---|---|---|---|
| 标准 | 高 | 毫秒级 | 热数据：网站图片 |
| 低频 | 中 | 毫秒级 | 月访问 1-2 次：月度报表 |
| 归档 | 最低 | 需先恢复 | 冷数据：合规归档 |

**三种访问方式**：控制台（拖拽上传）、命令行 obsutil、API/SDK（程序调用）。

```
# obsutil 命令行示例
obsutil config -i=AK -k=SK -e=obs.cn-north-4.myhuaweicloud.com   # 配置密钥
obsutil cp /data/web.log obs://my-bucket/logs/                    # 上传文件
obsutil ls obs://my-bucket                                        # 列举对象
```

**典型考法**：创建桶 → 上传网页文件 → 开启**静态网站托管** → 浏览器直接访问；或配置**生命周期规则**（30 天后自动转低频/归档）。

### 4.5 RDS 关系型数据库

**一句话定义**：RDS 是华为云"帮你运维"的数据库——不用自己装 MySQL、不用操心主从复制和备份，点点鼠标就有高可用实例。

**支持的引擎**：MySQL、PostgreSQL、SQL Server、GaussDB（华为自研）。

**核心操作流程**：

1. 控制台 → RDS → 购买实例：选引擎版本、规格、存储，**部署在与 ECS 相同的 VPC**
2. 配置安全组：放行 TCP 3306（MySQL 默认端口）
3. 创建数据库账号，或开启白名单
4. 在 ECS 上内网连接测试：

```bash
mysql -h 192.168.1.100 -P 3306 -u dbuser -p    # -h 是 RDS 内网 IP
```

**关键能力**：

| 能力 | 说明 |
|---|---|
| 主备高可用 | 主实例挂了自动切备实例 |
| 自动备份 | 按策略全量+增量备份，可恢复到时间点 |
| 只读实例 | 读写分离：读多写少的场景加只读分摊压力 |

**常见坑**：ECS 和 RDS **必须同 VPC 才能内网互通**；跨 VPC 要用对等连接，比赛通常不折腾。

### 4.6 ELB 弹性负载均衡

**一句话定义**：ELB 是放在多台服务器前面的"交通分流员"，把用户请求分发到健康的后端机器，一台挂了流量自动切走。

**三层概念**：

1. **监听器（Listener）**：定协议和端口——L4（TCP/UDP，转发快）或 L7（HTTP/HTTPS，可按 URL 路径转发）
2. **后端服务器组**：挂多台 ECS + 各自权重（后端端口如 80）
3. **健康检查**：定期探测后端（协议/端口/路径，如 `GET /health`），失败自动摘除

**调度策略**：轮询（默认）、最少连接、源 IP 哈希。

**典型考法**：给两台 Web ECS 前面加 ELB → 用浏览器多次刷新看到两个页面交替出现 → 关掉一台 ECS，验证服务不中断。

### 4.7 AS 弹性伸缩

**一句话定义**：AS 按你定的规则自动增减 ECS 数量——CPU 高了自动扩容，流量回落自动缩容，配合 ELB 实现"流量洪峰自动扛"。

**四大件**：

| 组件 | 说明 |
|---|---|
| 伸缩组 | 一批同质 ECS 的"池子"，需绑定 VPC/子网，通常关联 ELB |
| 伸缩配置 | 扩容出来的新机器长什么样（镜像、规格、登录方式） |
| 伸缩策略 | 告警式（CPU>70% 扩 1 台）/ 定时式（每天 19:00 扩）/ 周期式（每周五缩） |
| 期望实例数 | 伸缩组维持的机器数量，策略触发时自动加减 |

**注意冷却时间**：扩容后的一小段时间内不再触发下一次扩容，防止震荡。

### 4.8 IMS 镜像服务

**一句话定义**：镜像是 ECS 的"整盘克隆模板"——把一台配好的机器做成镜像，之后批量"复制"出 N 台一模一样的机器。

| 镜像类型 | 来源 |
|---|---|
| 公共镜像 | 华为云官方提供的纯操作系统 |
| 私有镜像 | 自己从 ECS/外部导入制作 |
| 共享镜像 | 别的账号共享给你 |
| 市场镜像 | 第三方预装了软件的镜像 |

**典型考法**：在一台 ECS 上装好 Web 环境 → 制作私有镜像 → 用该镜像再发放 3 台 ECS，验证全部能直接提供网页服务——比一台台手装快 10 倍。

### 4.9 CCE 云容器引擎与 Kubernetes（比赛拉开差距的部分）

**容器 vs 虚拟机**：

| 对比 | 虚拟机（ECS） | 容器 |
|---|---|---|
| 启动速度 | 分钟级 | 秒级 |
| 体量 | 每个 GB 级（含完整 OS） | MB 级（只打包应用+依赖） |
| 隔离性 | 强（独立内核） | 进程级（共享内核） |
| 密度 | 一台物理机十几台 | 一台节点跑几十个 |

**CCE（Cloud Container Engine）**：华为云托管的 Kubernetes 集群——控制面（Master）托管免运维，你只需要买"节点"（Node，本质是装了容器运行时的 ECS）。

**K8s 核心对象速记**：

| 对象 | 一句话 |
|---|---|
| Pod | 最小调度单元，一个或一组容器 |
| Deployment | 管 N 个 Pod 副本，挂了自动拉起新的 |
| Service | 给一组 Pod 一个固定访问入口（ClusterIP/NodePort/LoadBalancer） |
| Ingress | 七层路由：按域名/路径转发 |
| ConfigMap/Secret | 配置和密码与镜像分离 |

**典型部署清单（web.yaml）**：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels: {app: web}
  template:
    metadata:
      labels: {app: web}
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  type: LoadBalancer      # 自动关联 ELB，外网可访问
  selector: {app: web}
  ports:
  - port: 80
    targetPort: 80
```

```bash
kubectl apply -f web.yaml        # 部署
kubectl get pods -o wide         # 看 Pod 状态（Running 才算成）
kubectl describe pod web-xxx     # 排障：镜像拉取失败/资源不足看这里
kubectl logs web-xxx             # 看容器日志
```

**SWR（镜像仓库）**：自己 `docker build` 的镜像 push 到 SWR，CCE 拉取部署——比赛常考"把自制镜像跑进集群"。

### 4.10 IAM 身份认证管理

**一句话定义**：IAM 管的是"谁能用云上的什么资源"——主账号全权，子用户按授权来。

**核心模型**：**用户**（人）加入**用户组**，给用户组**授权**（策略/角色），策略定义能对哪些资源做什么操作。

- **最小权限原则**：只给完成任务所需的最小权限，比如运维只读策略、开发者只用 ECS
- **典型考法**：创建子用户并加入组 → 授予"OBS 只读"策略 → 验证该用户能看桶但不能删

### 4.11 云监控 CES 与日志 LTS

- **CES（云监控）**：所有资源的 CPU/内存/磁盘/网络指标都在这，可配**告警规则**（如 CPU>80% 发通知、触发 AS 扩容）
- **LTS（云日志）**：集中收集 ECS/容器日志，按关键词检索排障

### 4.12 ModelArts：AI 开发平台

**一句话定义**：ModelArts 把 AI 开发全流程（数据标注 → 训练 → 部署）都搬到了云上，不会算法也能用"预置模型"一键部署 AI 服务。

**比赛考法**（通常作为选做/加分）：部署一个预置服务（如 OCR 文字识别、图像分类），拿到 API 接口并成功调用；或在 Notebook 里跑一个简单训练任务。

## 5. 实验环境：华为云控制台实操入门

### 5.1 实验平台与账号

- **比赛环境**：组委会提供华为云沙箱账号，限时、有配额、比赛结束回收。平时别指望有"原题环境"，重在迁移能力
- **平时练习**：自己注册华为云账号并实名认证 → 资源一律选**按需计费** → 练完**立刻删除/退订**；华为云学院有免费沙箱实验（HCIA 配套实验手册），零成本练手
- **控制台要点**：顶部**搜索框**直达任意服务（最快入口）；左上角切换**区域**（资源是区域隔离的，别找错地方）；右上角费用中心盯消费

### 5.2 通用实验七步法

每道综合实验题都按这个节奏走，避免边做边想：

1. **读题画图**：把要求的架构画出来，标注 VPC 网段、子网 IP、ECS 规格、端口——先规划再动手
2. **建网络**：创建 VPC + 子网
3. **配安全组**：按题目端口表一次配齐（22/80/3306…）
4. **上计算**：购买 ECS / RDS 实例（核对 VPC、子网、镜像）
5. **部署应用**：SSH 登录装软件、上传代码
6. **联调验证**：`ping` / `curl` / `mysql` 逐层验证连通
7. **按题交付**：截图、记录实例名/IP，对照题目要求逐条核对

### 5.3 必做实验清单（练到肌肉记忆）

| # | 实验 | 覆盖服务 | 验收标准 |
|---|---|---|---|
| 1 | 购买 Linux ECS 并 SSH 远程登录 | ECS / EIP / 安全组 | 终端能登录 |
| 2 | 部署 HTTP 网站（httpd/WordPress） | ECS + EIP | `curl` 返回 200 |
| 3 | 挂载新数据盘并写入文件 | EVS | `df -h` 可见并重启不丢 |
| 4 | OBS 静态网站托管 | OBS | 浏览器访问桶 URL 出网页 |
| 5 | ECS + RDS 上线动态网站 | RDS | 网页能读写数据库 |
| 6 | ELB 分发 + AS 自动扩缩 | ELB / AS | 关一台机器服务不断 |
| 7 | 制作私有镜像批量发放 | IMS | 3 台新机直接提供网页 |
| 8 | CCE 部署容器化应用 | CCE / SWR | Service 域名可访问 |
| 9 | IAM 子账号权限验证 | IAM | 子用户只能看到指定服务 |
| 10 | CES 告警规则联动 | CES | 触发阈值收到通知 |

### 5.4 云上排障五步法（比赛关键能力）

配不通时，按层排查：

1. **网络可达**：EIP 绑了吗？安全组端口开了吗？（云上第一坑）
2. **服务运行**：`systemctl status httpd`，进程起了吗？
3. **配置正确**：监听端口对不对？路径、账号密码拼写对不对？
4. **依赖可用**：RDS 连得上吗？OBS 桶策略对吗？
5. **权限与配额**：IAM 有权限吗？配额（实例数/磁盘数）超了吗？

**常见故障排查案例**：

| 故障现象 | 可能原因 | 排查点 |
|---|---|---|
| SSH 连不上 ECS | 没绑 EIP / 安全组没开 22 / 密钥错误 | EIP 列表、安全组入方向、VNC 登录验证 |
| 网页打不开 | httpd 未启动 / 80 端口未放行 | `systemctl status`、安全组规则 |
| RDS 连接超时 | 与 ECS 不同 VPC / 安全组未放行 3306 | 网络拓扑、RDS 安全组 |
| ELB 后端显示异常 | 健康检查端口/路径配错 | 健康检查配置、后端端口 |
| Pod 一直 Pending | 节点资源不足 / 镜像拉取失败 | `kubectl describe pod` |
| OBS 拒绝访问 | 桶策略/ACL 未授权 | 桶策略、匿名读权限 |
| 创建资源报错配额不足 | 免费配额用完 | 删掉不用的资源再试 |

> 比赛拉开差距的不是"会不会买"，而是"出问题能不能 30 秒内定位到哪一层"。

## 6. 备赛最大难点与突破策略

### 6.1 最大难点

| 难点 | 具体表现 |
|---|---|
| **服务面太广** | 华为云服务 200+，比赛涉及几十个，入口、参数、联动关系记不住 |
| **参数细节坑多** | 区域/版本/计费/配额，选错一步推倒重来，浪费比赛时间 |
| **综合架构题** | 一道题串起 VPC+ECS+RDS+ELB+OBS，会用单个服务 ≠ 能组装架构 |
| **全英文环境** | 全球总决赛英文题面 + 英文控制台，服务名和报错都要能读 |
| **团队互踩** | 三人共用一个环境，一人改错另一人配好的资源 |
| **限时压力** | 8 小时从零搭完整架构，每道题都在倒计时 |

### 6.2 突破策略

**策略一：分工专攻，交叉覆盖**
- 3 人分工：1 人主攻计算+存储+镜像，1 人主攻网络+数据库，1 人主攻容器+AI+运维
- 但底盘（VPC/ECS/安全组）三人必须人人会——任何一道题都从底盘开始

**策略二：控制台肌肉记忆**
- 为高频服务各做一张"点单清单"：入口路径 → 必填参数 → 验收动作
- 练到看到题目就能报出"先建什么后建什么、每步填什么"

**策略三：规划先行，模板沉淀**
- 动手前先填"资源规划表"：名称、CIDR、IP、端口、规格全部落纸
- 每个实验沉淀三样：步骤清单、验证命令、踩过的坑

**策略四：整架构实战，刻意排障**
- 用 5.3 清单练单点，再串成完整架构限时做
- 复盘每次实验：哪一步反复看文档？哪里耗时最多？
- 队友互相"埋雷"（故意改错安全组/端口），练快速排障

**策略五：限时模拟，建立节奏**
- 严格按 8 小时做整套模拟题，切换控制台为英文界面
- 形成团队 SOP：谁读题拆解、谁搭网络、谁部署应用、谁验证交付

- 查漏补缺，回归各服务的"点单清单"
- 最后 3 天：只看自己的清单和笔记，不再学新内容
